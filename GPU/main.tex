\section{算法原理}

\subsection{数论变换}

NTT 是在有限域上执行的离散傅里叶变换。本实验选用
\[
q=998244353=119\times 2^{23}+1,
\qquad g=3,
\]
其中 $g$ 是模 $q$ 的原根。由于 $q-1$ 含有因子 $2^{23}$，本实验可处理的
radix-2 NTT 最大长度为 $2^{23}$。

对于长度为 $N$ 的变换，$N$ 次单位根为
\[
\omega_N=g^{(q-1)/N}\bmod q.
\]
每个蝶形运算为
\begin{align}
u &= a_i,\\
v &= a_{i+L/2}\omega_L^j \bmod q,\\
a_i &= (u+v)\bmod q,\\
a_{i+L/2} &= (u-v+q)\bmod q,
\end{align}
其中 $L$ 为当前阶段的蝶形长度。逆变换使用逆单位根，并在最后乘以
$N^{-1}\bmod q$。

\subsection{GPU 并行映射}

首先在 GPU 上执行位逆序置换。随后每个线程负责一个蝶形。设线程全局编号为
$t$，则线程对应的数据位置为
\begin{align}
h &= L/2,\\
\text{group} &= \lfloor t/h\rfloor,\\
j &= t\bmod h,\\
i_0 &= \text{group}\cdot L+j,\\
i_1 &= i_0+h.
\end{align}

同一阶段的蝶形彼此独立，因此可以并行执行。不同 workgroup 之间不存在可由块内
同步函数实现的全局屏障，所以普通版本每个 NTT 阶段启动一次 kernel。对于
$N=2^{20}$，一次正变换包含 20 次蝶形 kernel。

\subsection{旋转因子存储}

CPU 预先生成正变换和逆变换旋转因子表，然后通过 \texttt{hipMemcpy} 一次性复制
到 GPU 全局内存。第 $L$ 阶段第 $j$ 个蝶形使用的表下标为
\[
j\frac{N}{L}.
\]
这种方法避免了每个线程在 kernel 中执行模幂运算。旋转因子的生成时间和首次
主机到设备传输时间不计入纯 kernel 时间。

\subsection{Barrett 规约}

预计算
\[
\mu=\left\lfloor\frac{2^{64}}{q}\right\rfloor.
\]
对于 $x=ab$，利用 64 位乘法高位近似商：
\begin{align}
\widehat{m} &= \left\lfloor\frac{x\mu}{2^{64}}\right\rfloor,\\
r &= x-\widehat{m}q.
\end{align}
最后通过条件减法将 $r$ 调整到 $[0,q)$。GPU 使用高位乘法指令
\texttt{\_\_umul64hi}，避免运行时整数除法。

\subsection{Montgomery 规约}

令 $R=2^{32}$，并预计算
\[
q'=-q^{-1}\bmod R.
\]
对于 $t=ab$，Montgomery 规约为
\begin{align}
m &= (t\bmod R)q'\bmod R,\\
u &= \frac{t+mq}{R}.
\end{align}
若 $u\ge q$，再减去一次 $q$。输入数据、旋转因子和 $N^{-1}$ 都提前转换为
Montgomery 形式 $xR\bmod q$，整个 NTT 始终在 Montgomery 域中计算，最后统一
转换回普通表示。这样可以避免在每次模乘前后进行域转换。

\subsection{LDS 分块}

根据 workgroup 测试结果，分块版本采用 128 个线程和 256 个元素的 tile。每个
线程负责两个元素的加载或一组蝶形，将前 8 个阶段（$L=2,4,\ldots,256$）融合
到一个 kernel，并在 LDS 中完成。阶段之间使用
\texttt{\_\_syncthreads()}。从 $L=512$ 开始，蝶形会跨越 tile，仍需使用全局
内存和独立 kernel。

\section{程序实现与正确性验证}

程序包含以下版本：

\begin{enumerate}
  \item CPU 串行 NTT；
  \item GPU 运行时 \texttt{\% mod} baseline；
  \item GPU Barrett 规约版本；
  \item GPU Montgomery 规约版本；
  \item GPU Montgomery + LDS tiled 版本。
\end{enumerate}

\subsection{三部分优化的核心代码}

\subsubsection{优化一：预处理旋转因子}

旋转因子只与模数、变换长度和变换方向有关。程序在 CPU 上一次性生成正、逆变换
旋转因子表，随后复制到 GPU 全局内存。kernel 通过下标直接查表，从而避免每个
线程在每个阶段重复执行模幂运算。

\begin{lstlisting}[language=C++,caption={旋转因子预计算与传输}]
std::vector<u32> make_twiddles(int n, bool inverse) {
    std::vector<u32> twiddles(n / 2);
    u32 omega = mod_pow(ROOT, (MOD - 1) / n);

    if (inverse) {
        omega = mod_pow(omega, MOD - 2);
    }

    twiddles[0] = 1;
    for (int i = 1; i < n / 2; ++i) {
        twiddles[i] = static_cast<u32>(
            static_cast<u64>(twiddles[i - 1])
            * omega % MOD
        );
    }
    return twiddles;
}

std::vector<u32> forward_twiddles =
    make_twiddles(N, false);
std::vector<u32> inverse_twiddles =
    make_twiddles(N, true);

hipMalloc(
    &device_forward_twiddles,
    forward_twiddles.size() * sizeof(u32)
);
hipMemcpy(
    device_forward_twiddles,
    forward_twiddles.data(),
    forward_twiddles.size() * sizeof(u32),
    hipMemcpyHostToDevice
);
\end{lstlisting}

对于长度为 \texttt{length} 的阶段，线程使用
\texttt{j * (n / length)} 作为旋转因子下标。正、逆变换分别保存一张表，避免在
GPU 上求逆。预处理和首次传输发生在计时区间之外，正式性能表测量 steady-state
NTT kernel 时间。

\subsubsection{优化二：蝶形运算并行化}

长度为 $N$ 的每个阶段包含 $N/2$ 个互不冲突的蝶形。程序将一个蝶形映射给一个
GPU 线程，使用一维 grid 覆盖所有蝶形。线程先计算所在蝶形组和组内偏移，再完成
两次读、一次模乘、模加和模减。

\begin{lstlisting}[language=C++,caption={一个线程负责一个蝶形运算}]
__global__ void butterfly_kernel(
    u32* data,
    const u32* twiddles,
    int n,
    int length,
    u32 mod
) {
    int tid = blockIdx.x * blockDim.x + threadIdx.x;
    if (tid >= n / 2) return;

    int half = length / 2;
    int group = tid / half;
    int j = tid % half;
    int first = group * length + j;
    int second = first + half;
    int twiddle_index = j * (n / length);

    u32 left = data[first];
    u32 right = static_cast<u32>(
        static_cast<u64>(data[second])
        * twiddles[twiddle_index] % mod
    );

    u32 sum = left + right;
    if (sum >= mod) sum -= mod;

    u32 difference =
        left >= right ? left - right
                      : left + mod - right;

    data[first] = sum;
    data[second] = difference;
}
\end{lstlisting}

不同阶段存在数据依赖，因此普通版本每个阶段启动一次 kernel，以 kernel 边界完成
全局同步。workgroup 大小通过实测选择，而不是直接使用硬件允许的最大值。

\begin{lstlisting}[language=C++,caption={逐阶段启动并行蝶形 kernel}]
int butterflies = n / 2;
int grid = (butterflies + BLOCK_SIZE - 1)
           / BLOCK_SIZE;

for (int length = 2; length <= n; length <<= 1) {
    hipLaunchKernelGGL(
        butterfly_kernel,
        dim3(grid), dim3(BLOCK_SIZE), 0, 0,
        device_data, device_twiddles,
        n, length, MOD
    );
}
\end{lstlisting}

实验还实现了 LDS tiled 版本：以 128 个线程处理 256 个元素，将前 8 个阶段融合
到一个 workgroup 内。该版本验证正确，但同步和 LDS 搬运开销使其在本设备上慢于
普通并行版本。

\subsubsection{优化三：Barrett 与 Montgomery 模乘}

Barrett 规约预计算 $\mu=\lfloor 2^{64}/q\rfloor$，使用乘法高位近似商，避免
运行时整数除法。代码如下。

\begin{lstlisting}[language=C++,caption={Barrett 模乘}]
constexpr u64 BARRETT_MU =
    18446744073709551615ULL / MOD;

__device__ __forceinline__
u32 barrett_mul(u32 left, u32 right) {
    u64 product = static_cast<u64>(left) * right;

    u64 quotient = __umul64hi(
        static_cast<unsigned long long>(product),
        static_cast<unsigned long long>(BARRETT_MU)
    );

    u64 remainder =
        product - quotient * static_cast<u64>(MOD);

    if (remainder >= MOD) remainder -= MOD;
    return static_cast<u32>(remainder);
}
\end{lstlisting}

Montgomery 规约使用 $R=2^{32}$，预计算 $-q^{-1}\bmod R$，通过低 32 位乘法和
右移完成规约。

\begin{lstlisting}[language=C++,caption={Montgomery 规约与模乘}]
constexpr u32 inverse_mod_2_32(u32 value) {
    u32 inverse = 1;
    for (int i = 0; i < 5; ++i) {
        inverse *= 2U - value * inverse;
    }
    return inverse;
}

constexpr u32 MONT_NINV =
    0U - inverse_mod_2_32(MOD);
constexpr u32 MONT_R_MOD =
    static_cast<u32>((1ULL << 32) % MOD);

__host__ __device__ __forceinline__
u32 montgomery_reduce(u64 value) {
    u32 m = static_cast<u32>(value) * MONT_NINV;
    u64 reduced =
        (value + static_cast<u64>(m) * MOD) >> 32;

    if (reduced >= MOD) reduced -= MOD;
    return static_cast<u32>(reduced);
}

__host__ __device__ __forceinline__
u32 montgomery_mul(u32 left, u32 right) {
    return montgomery_reduce(
        static_cast<u64>(left) * right
    );
}
\end{lstlisting}

为避免域转换抵消优化收益，输入数据和旋转因子在 NTT 开始前统一转换为
$xR\bmod q$，整个正、逆变换均保留在 Montgomery 域中，最终仅转换一次。

\begin{lstlisting}[language=C++,caption={Montgomery 域的批量预转换与最终转换}]
u32 to_montgomery(u32 value) {
    return static_cast<u32>(
        static_cast<u64>(value) * MONT_R_MOD % MOD
    );
}

for (int i = 0; i < N; ++i) {
    montgomery_input[i] = to_montgomery(input[i]);
}
for (u32& value : forward_twiddles) {
    value = to_montgomery(value);
}

// Convert only after the complete NTT has finished.
for (u32& value : gpu_result) {
    value = montgomery_reduce(value);
}
\end{lstlisting}

在蝶形 kernel 中，只需将普通模乘替换为对应的 Barrett 或 Montgomery 设备函数。
线程映射和数据布局保持不变，因此能够单独比较模乘策略的影响。

所有 HIP 调用均检查返回值，并在 kernel 启动后检查
\texttt{hipGetLastError()}。GPU 时间使用 HIP Event 测量。测试采用固定随机种子，
保证不同版本处理相同输入。

CPU 小规模测试的结果为
\begin{verbatim}
Forward NTT:
36 894301004 346334868 201631260 998244349 796613085 651909477 103943341
Inverse NTT:
1 2 3 4 5 6 7 8
Verification: PASSED
\end{verbatim}

在 $N=2^{20}$ 时，普通取模、Barrett、Montgomery 和 LDS tiled 版本均满足：
\begin{itemize}
  \item GPU 正变换结果与 CPU 逐元素一致；
  \item GPU 正变换后执行逆变换能够恢复原始输入；
  \item 独立模乘测试中三种 GPU 实现均与 CPU 参考结果一致。
\end{itemize}

\section{实验结果与分析}

\subsection{Workgroup 大小}

固定 $N=2^{20}$，使用 Montgomery 版本测试不同 workgroup 大小，每种配置运行
10 次。

\begin{table}[H]
  \centering
  \caption{Workgroup 大小对正变换时间的影响}
  \begin{tabular}{rrr}
    \toprule
    Workgroup 大小 & 平均时间/ms & 标准差/ms \\
    \midrule
    64   & 1.2249 & 0.0578 \\
    128  & 1.1147 & 0.0231 \\
    256  & 1.1331 & 0.0317 \\
    512  & 1.1773 & 0.0457 \\
    1024 & 1.1988 & 0.0359 \\
    \bottomrule
  \end{tabular}
\end{table}

128 线程取得最佳结果。较小 workgroup 的并行度不足，而较大 workgroup 会降低
调度灵活性和活跃 workgroup 数量。由于设备使用 wave32，所有测试值均为
wavefront 大小的整数倍。

\subsection{完整 NTT 的模乘与 LDS 优化}

固定 $N=2^{20}$，预热 2 次后交错运行各版本 10 次，结果如下。

\begin{table}[H]
  \centering
  \caption{完整 NTT 的不同 GPU 实现}
  \footnotesize
  \setlength{\tabcolsep}{2pt}
  \resizebox{\textwidth}{!}{%
  \begin{tabular}{lrrrrr}
    \toprule
    方法 & 正变换/ms & 标准差 & 逆变换/ms & 标准差 & 正变换相对 baseline \\

    Runtime modulo   & 1.1523 & 0.0295 & 0.7766 & 0.0022 & 1.000 \\
    Barrett          & 1.1348 & 0.0416 & 0.7522 & 0.0024 & 1.015 \\

完整正变换中 Barrett 和 Montgomery 的提升较小。原因是完整 NTT 不仅包含模乘，

总时间的一部分，因此算术优化被其他开销稀释。

LDS tiled 版本比 baseline 慢约 $4.3\%$。虽然它把前 8 个阶段融合为一次 kernel，
但增加了 LDS 搬运和多次 workgroup 屏障。对于当前设备和问题规模，这些开销超过
了减少 kernel 启动次数带来的收益。因此实验保留该结果，不将分块本身等同于必然
加速。

\section{误差来源与实验局限}

\begin{enumerate}
  \item GPU 表格主要报告纯 kernel 时间，不包含首次 H2D/D2H 传输、旋转因子生成、
        设备内存分配和 HIP 上下文初始化；
  \item 独立 Montgomery 模乘不包含进入和退出 Montgomery 域的时间，反映的是 NTT
        steady-state 场景；
  \item CPU baseline 为单线程实现，未使用 SIMD 或多线程；
  \item 本实验固定模数为 998244353,较为单一；
  \item 完整 NTT 的模乘差异较小，部分差异与标准差处于同一数量级，因此不应仅凭
        单次测试宣称显著加速。
\end{enumerate}

\section{结论}

本实验完成了 CPU 和 HIP GPU 上的 NTT，并实现了旋转因子 GPU 查表、
Barrett 规约、Montgomery 规约和 LDS 分块。所有 GPU 版本均通过 CPU 对照和
正逆变换恢复测试。

在独立模乘场景中，Barrett 和 Montgomery 相对 GPU 运行时取模分别取得
$2.156$ 倍和 $5.350$ 倍加速，说明消除整数除法十分有效。在完整 NTT 中，访存、
位逆序和 kernel 启动占据较大比例，模乘优化带来的整体提升有限。GPU 对中大规模
NTT 仍表现出明显优势，在 $N=2^{20}$ 时相对单线程 CPU 达到 $26.66$ 倍加速。

LDS tiled 版本在当前实现中下降约 $4.3\%$，表明共享内存优化必须综合考虑同步、
数据搬运和 occupancy，而不能只考虑减少全局内存访问或 kernel 次数。rocprofv3
进一步表明蝶形计算和位逆序分别占约 $78.90\%$ 和 $20.34\%$，后续可以考虑使用
Stockham NTT 消除独立位逆序、使用 wave shuffle 融合小规模阶段，以及针对不同
$N$ 自动选择 tile 和 workgroup 配置。
