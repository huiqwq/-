\section{实验背景与目标}

本实验选题为数论变换 NTT（Number Theoretic Transform）的 MPI 并行化。NTT 常用于整数或多项式卷积计算，可以将朴素卷积的 $O(n^2)$ 复杂度降低到 $O(n\log n)$。前序实验已经完成了 Pthread、OpenMP、SIMD 以及 CRT 相关优化，本次实验在原有代码框架基础上引入 MPI，重点分析多进程任务划分和通信同步对性能的影响。

给定两个长度为 $n$ 的多项式 $A(x)$ 和 $B(x)$，实验目标是在模数 $P$ 下计算：
\[
C(x)=A(x)B(x)\pmod P
\]

本次实验主要完成以下工作：
\begin{enumerate}
    \item 在原有 OpenMP、SIMD、CRT 代码框架上实现 MPI 并行版本；
    \item 实现 CRT 模数级 MPI 并行和 NTT stage 级 MPI 并行两类任务划分；
    \item 在 stage 级 MPI 并行基础上加入 Barrett 规约优化；
    \item 在 Barrett 版本基础上实现 DIF/DIT 流程优化，减少显式位逆序置换；
    \item 在实现的第一个NTT版本的基础上也实现DIF/DIT优化；
    \item 通过 qsub 提交到 ARM 服务器运行，比较不同版本的正确性和性能。
\end{enumerate}

\section{算法基础}

\subsection{NTT 基本流程}

NTT 将多项式从系数表示转换到点值表示。两个多项式分别变换后，在点值域中逐点相乘，再通过逆 NTT 转换回系数表示：
\[
A \xrightarrow{\mathrm{NTT}} \hat{A},\quad
B \xrightarrow{\mathrm{NTT}} \hat{B}
\]
\[
\hat{C}[i]=\hat{A}[i]\hat{B}[i]\pmod P
\]
\[
C \xleftarrow{\mathrm{INTT}} \hat{C}
\]

NTT 的核心是分层 butterfly 计算。对于长度为 \texttt{len} 的一层，设 \texttt{half=len/2}，典型 butterfly 操作为：
\[
x=f[base+k]
\]
\[
y=f[base+k+half]\cdot w_k\pmod p
\]
\[
f[base+k]=x+y\pmod p
\]
\[
f[base+k+half]=x-y\pmod p
\]

同一层中不同 butterfly block 之间互不依赖，可以并行；不同层之间存在严格依赖，必须同步后才能进入下一层。

\subsection{CRT 大模数处理}

实验数据中存在较大的目标模数，例如：
\[
P=1337006139375617
\]
该模数不适合直接作为单一 NTT 模数。为支持大模数卷积，程序保留前序实验中的四模数 CRT 框架。选取四个 NTT 友好小模数：
\[
998244353,\quad 1004535809,\quad 469762049,\quad 1224736769
\]
分别在每个小模数下计算卷积结果，再通过中国剩余定理恢复到目标模数 $P$ 下。

四模数 CRT 的整体流程为：
\begin{enumerate}
    \item 对每个小模数 $p_i$，将输入系数映射到模 $p_i$ 下；
    \item 分别执行 NTT、点值乘法和逆 NTT，得到 residue 数组；
    \item 对每个输出系数位置，使用 CRT 合并四个 residue；
    \item 将恢复出的整数结果对目标模数 $P$ 取模。
\end{enumerate}

\section{MPI 编程模型与通信设计}

MPI（Message Passing Interface）采用多进程并行模型。程序启动后，每个进程都执行同一份可执行文件，但通过 \texttt{MPI\_Comm\_rank} 得到不同的 rank，通过 \texttt{MPI\_Comm\_size} 得到总进程数，从而决定自己负责的数据范围和计算任务。本实验中的 MPI 程序均使用 \texttt{mpic++} 编译，并通过 qsub 作业脚本中的 \texttt{mpiexec -np} 启动。

与 OpenMP 不同，MPI 进程之间默认不共享内存。rank 0 读到的输入数组不会自动出现在其他 rank 中，必须通过显式通信传递。对于 NTT 实验，通信方式主要分为三类：
\begin{enumerate}
    \item \textbf{广播输入}：rank 0 读取样例后，使用 \texttt{MPI\_Bcast} 将 $n$、目标模数 $P$、输入数组 $a$ 和 $b$ 发送给所有进程，保证各进程拥有相同初始数据；
    \item \textbf{点对点收集}：在 CRT 模数级并行中，非 0 进程完成自己负责的小模数 NTT 后，通过 \texttt{MPI\_Send} 把 residue 数组发回 rank 0，rank 0 用 \texttt{MPI\_Recv} 接收；
    \item \textbf{集体同步}：在 butterfly stage 级并行中，同一层 NTT 被拆给多个进程计算。由于下一层依赖完整数组，每层结束后必须通过 \texttt{MPI\_Allgatherv} 汇总所有进程的片段，使每个进程重新获得完整的数组视图。
\end{enumerate}

因此，本实验的 MPI 优化核心不是简单增加进程数，而是选择合适的任务粒度。粗粒度划分通信少，但最多只能利用有限数量的任务；细粒度划分可以让更多进程参与同一个 NTT，但会引入频繁同步。后续五个版本正是围绕这两类思路展开。

\section{两类 MPI 优化形式及版本实现}

\subsection{第一类：CRT 模数级任务并行}

大模数卷积不能直接在目标模数 $P=1337006139375617$ 下进行普通 NTT，因此原有代码采用四个 NTT 友好的小模数分别计算，再用 CRT 合并结果。四个小模数下的 NTT 互相独立，这是最自然的 MPI 任务划分点。

\subsubsection{v1：四个进程分别执行四个小模数 NTT}

v1 是本实验的基础 MPI 版本。它的核心思想是在 CRT 外层做任务并行：四个小模数 NTT 之间相互独立，因此可以交给不同 MPI 进程分别计算。需要注意的是，v1 并不是纯 MPI 串行内部计算版本，它保留了前序实验中已经实现的 OpenMP 和 SIMD 优化；也就是说，v1 的并行结构是“外层 MPI 进程级并行 + 进程内部 OpenMP/SIMD”。

\paragraph{MPI 进程创建与初始化}

MPI 进程不是在代码中手动 \texttt{fork} 创建的，而是由运行命令中的 \texttt{mpiexec -np} 启动。例如 qsub 脚本中使用：
\begin{lstlisting}[language=bash]
/usr/local/bin/mpiexec -np 4 -machinefile $PBS_NODEFILE /home/${USER}/main 0 4 1
\end{lstlisting}
其中 \texttt{-np 4} 表示启动 4 个 MPI 进程。每个进程都会执行同一个 \texttt{main} 函数，但进程编号不同。代码开头通过 \texttt{MPI\_Init} 初始化 MPI 运行环境，然后通过 \texttt{MPI\_Comm\_rank} 和 \texttt{MPI\_Comm\_size} 获得当前进程编号和总进程数：
\begin{lstlisting}[language=C++,title=v1 的 MPI 初始化]
int main(int argc, char *argv[]) {
    MPI_Init(&argc, &argv);
    init_openmp_runtime();

    int rank, size;
    MPI_Comm_rank(MPI_COMM_WORLD, &rank);
    MPI_Comm_size(MPI_COMM_WORLD, &size);
    ...
    MPI_Finalize();
    return 0;
}
\end{lstlisting}
\texttt{rank} 用来区分不同进程的职责。rank 0 作为主进程，负责读入样例、检查答案、输出结果和最终 CRT 合并；其他 rank 主要负责接收输入并完成分配到的小模数 NTT。程序结束前调用 \texttt{MPI\_Finalize} 释放 MPI 运行环境。

\paragraph{输入广播}

由于 MPI 进程之间不共享内存，rank 0 从文件读入的 $n$、目标模数 $P$、数组 $a$ 和 $b$ 不会自动出现在其他进程中。因此 v1 在每个样例读入后调用 \texttt{bcast\_input\_for\_mpi}，使用 \texttt{MPI\_Bcast} 将输入广播给所有进程：
\begin{lstlisting}[language=C++,title=v1 的输入广播]
void bcast_input_for_mpi(u64 *a, u64 *b, int *n, u64 *p, int rank) {
    MPI_Bcast(n, 1, MPI_INT, 0, MPI_COMM_WORLD);
    MPI_Bcast(p, 1, MPI_UINT64_T, 0, MPI_COMM_WORLD);
    MPI_Bcast(a, *n, MPI_UINT64_T, 0, MPI_COMM_WORLD);
    MPI_Bcast(b, *n, MPI_UINT64_T, 0, MPI_COMM_WORLD);
}
\end{lstlisting}
其中最后一个参数中的 0 表示广播源是 rank 0。广播完成后，所有进程都拥有同一份输入数据，可以独立计算自己负责的小模数。

\paragraph{CRT 小模数任务划分与结果回传}

每个小模数任务的归属由：
\begin{lstlisting}[language=C++]
owner = mod_id % size;
\end{lstlisting}
确定。当使用 \texttt{np=4} 时，四个小模数刚好分别由 rank 0、rank 1、rank 2 和 rank 3 负责。每个 rank 在本地独立完成：
\[
A_i \xrightarrow{NTT} \hat{A_i},\quad
B_i \xrightarrow{NTT} \hat{B_i},\quad
\hat{C_i}[k]=\hat{A_i}[k]\hat{B_i}[k]\pmod {p_i},\quad
C_i \xleftarrow{INTT} \hat{C_i}
\]
其中 $p_i$ 是该 rank 负责的小模数。

非 0 进程计算完 residue 后，通过 \texttt{MPI\_Send} 发送给 rank 0；rank 0 通过 \texttt{MPI\_Recv} 接收，并在四个 residue 都得到后进行 CRT 合并：
\begin{lstlisting}[language=C++,title=v1 的 CRT 模数级 MPI 通信]
for (int mod_id = 0; mod_id < CRT_CNT; ++mod_id) {
    int owner = mod_id % size;
    if (rank == owner) {
        vector<u64> local;
        multiply_mod_ntt(a, b, local, n, CRT_MODS[mod_id]);
        if (rank == 0) residues[mod_id].swap(local);
        else MPI_Send(local.data(), result_len, MPI_UINT64_T,
                      0, 100 + mod_id, MPI_COMM_WORLD);
    }
    if (rank == 0 && owner != 0) {
        residues[mod_id].resize(result_len);
        MPI_Recv(residues[mod_id].data(), result_len, MPI_UINT64_T,
                 owner, 100 + mod_id, MPI_COMM_WORLD,
                 MPI_STATUS_IGNORE);
    }
}
\end{lstlisting}
这里的 \texttt{100 + mod\_id} 是消息标签，用来区分不同小模数的 residue。由于每个小模数只需要发送一次结果数组，v1 的通信过程可以概括为“开始一次广播，结束一次收集”，没有在 NTT 每一层进行全局同步。

计时时，v1 使用 \texttt{MPI\_Barrier} 让所有进程在同一位置开始和结束计时，并使用 \texttt{MPI\_Wtime} 记录 MPI 程序的墙钟时间：
\begin{lstlisting}[language=C++]
MPI_Barrier(MPI_COMM_WORLD);
double start = MPI_Wtime();
poly_multiply_crt_mpi_modparallel(a, b, ab, n_, p_);
MPI_Barrier(MPI_COMM_WORLD);
double end = MPI_Wtime();
\end{lstlisting}

\paragraph{v1 中已有的 OpenMP 与 SIMD 优化}

v1 的 MPI 划分只决定“小模数任务交给哪个进程”，而每个进程内部的小模数 NTT 仍然使用 OpenMP 和 SIMD 优化。程序通过 \texttt{init\_openmp\_runtime} 读取 \texttt{OMP\_NUM\_THREADS}，限制线程数不超过 8，并关闭动态线程调整：
\begin{lstlisting}[language=C++]
void init_openmp_runtime() {
    omp_set_dynamic(0);
    omp_set_num_threads(get_omp_threads());
    omp_set_schedule(omp_sched_guided, 64);
}
\end{lstlisting}

在 NTT 计算中，butterfly block 之间相互独立，因此可以用 OpenMP 并行分配：
\begin{lstlisting}[language=C++]
#pragma omp parallel for schedule(static)
for (int block = 0; block < blocks; ++block) {
    // butterfly block
}
\end{lstlisting}
当 block 数较少时，代码还会按照总 butterfly 数量手动划分给不同线程，减少线程空转。

SIMD 优化主要出现在内层 butterfly、点值乘法和结果拷贝位置，例如：
\begin{lstlisting}[language=C++]
#pragma omp simd
for (int k = 0; k < half; ++k) {
    u64 x = f[base + k];
    u64 y = mul_mod_ntt(f[base + k + half], roots[k], mod);
    f[base + k] = add_mod(x, y, mod);
    f[base + k + half] = sub_mod(x, y, mod);
}

#pragma omp simd
for (int i = 0; i < limit; ++i) {
    A[i] = mul_mod_ntt(A[i], B[i], nm.mod);
}
\end{lstlisting}
此外，rank 0 在 CRT 合并阶段也使用 OpenMP 对不同输出系数并行处理：
\begin{lstlisting}[language=C++]
#pragma omp parallel for schedule(guided, 256)
for (int i = 0; i < result_len; ++i) {
    u64 r[CRT_CNT];
    for (int j = 0; j < CRT_CNT; ++j) r[j] = residues[j][i];
    ab[i] = crt_combine_one(r, target_mod, inv_prod_mod);
}
\end{lstlisting}

因此，v1 的特点是通信结构简单、同步次数少，同时在单个 MPI 进程内部仍保留线程级和指令级优化。它的缺点是 MPI 粒度较粗，并行任务数受四个 CRT 小模数限制；但正因为通信少，实测中它比频繁层间同步的 stage 级 MPI 版本更稳定。

\subsubsection{v5：在 v1 基础上进一步结合 DIF/DIT、OpenMP 和 SIMD}

v5 仍然属于第一类优化，MPI 层面的任务划分和通信方式与 v1 相同：rank 0 广播输入，四个 rank 分别处理四个小模数，非 0 rank 将 residue 发回 rank 0。因此 v5 没有重新引入 NTT 层间的 MPI 同步，而是在每个 MPI 进程内部优化小模数 NTT 的执行效率。

v5 相比 v1 的主要改动是使用 DIF/DIT 流程，并继续保留进程内 OpenMP/SIMD 优化。传统 DIT 正变换通常需要先做 \texttt{bit\_reverse}，该步骤会产生不连续访存和大量元素交换。DIF（Decimation in Frequency）正变换从大区间向小区间递减计算，不需要初始位逆序，但输出为 bit-reversed 顺序；DIT（Decimation in Time）逆变换可以直接接收 bit-reversed 顺序输入，并输出正常顺序。因此正变换使用 DIF、逆变换使用 DIT 时，可以省掉显式 \texttt{bit\_reverse}：
\begin{enumerate}
    \item $A$ 和 $B$ 都经过 DIF 正变换，得到相同的 bit-reversed 顺序频域数组；
    \item 两个数组顺序一致，所以可以直接逐点相乘；
    \item 逆变换使用 DIT，将 bit-reversed 顺序输入还原为正常顺序系数。
\end{enumerate}

在进程内部并行方面，v5 沿用并强化 OpenMP 和 SIMD。外层 butterfly block 之间没有数据依赖，适合用 OpenMP 分配给多个线程；同一个 block 内部的若干 butterfly 操作形态一致，适合用 SIMD 提示编译器向量化。典型结构如下：
\begin{lstlisting}[language=C++,title=v5 的进程内 OpenMP/SIMD 结构]
#pragma omp parallel for schedule(static)
for (int block = 0; block < blocks; ++block) {
    int base = block * len;
    #pragma omp simd
    for (int k = 0; k < half; ++k) {
        // butterfly
    }
}
\end{lstlisting}

点值乘法阶段也采用相同思路：
\begin{lstlisting}[language=C++]
#pragma omp parallel for simd schedule(static)
for (int i = 0; i < limit; ++i) {
    A[i] = mul_mod_ntt(A[i], B[i], mod);
}
\end{lstlisting}

因此 v5 的整体结构可以表示为：
\[
\text{CRT 模数级 MPI 并行}+
\text{进程内 OpenMP}+
\text{SIMD 向量化}+
\text{DIF/DIT 流程优化}
\]
它保留了 v1 的低通信优势，同时继续挖掘单个小模数 NTT 内部的线程级和指令级并行能力。实测中，\texttt{np=4, OMP\_NUM\_THREADS=2} 的配置效果最好，说明在该服务器上适度多线程可以提升每个 MPI 进程的计算能力；但线程数继续增大后，会受到线程同步、内存带宽和节点资源调度的限制。

\subsection{第二类：NTT butterfly stage 级并行}

第二类优化不再把一个小模数 NTT 完整交给单个进程，而是让所有 MPI 进程共同完成每个小模数下的 NTT。它的并行点来自 NTT 每一层中的 butterfly block。同一层内不同 block 互不依赖，可以分给不同 rank；但不同层之间有严格依赖，必须在每层结束后同步完整数组。

\subsubsection{v2：按 butterfly block 划分 MPI 任务}

v2 中，对于每个 CRT 小模数，所有 rank 都参与正 NTT、点值乘法和逆 NTT。设当前层长度为 \texttt{len}，则该层共有：
\[
blocks=\frac{N}{len}
\]
个 butterfly block。rank 为 $r$ 的进程负责：
\[
\left[
\frac{blocks\cdot r}{size},
\frac{blocks\cdot (r+1)}{size}
\right)
\]
范围内的 block。代码中对应为：
\begin{lstlisting}[language=C++,title=v2 的 stage 级 block 划分]
int blocks = n / len;
int block_l = blocks * rank / size;
int block_r = blocks * (rank + 1) / size;

for (int block = block_l; block < block_r; ++block) {
    int base = block * len;
    for (int k = 0; k < half; ++k) {
        // butterfly
    }
}
\end{lstlisting}

每个进程只修改自己负责的数组片段。由于下一层 butterfly 可能访问上一层由其他进程计算出的数据，当前层结束后必须执行全局同步。本实验使用 \texttt{MPI\_Allgatherv}，使所有进程都得到同步后的完整数组：
\begin{lstlisting}[language=C++,title=v2 的层间同步]
MPI_Allgatherv(f.data() + displs[rank], counts[rank], MPI_UINT64_T,
               gathered.data(), counts.data(), displs.data(), MPI_UINT64_T,
               MPI_COMM_WORLD);
f.swap(gathered);
\end{lstlisting}

点值乘法阶段也按连续区间分给各 rank，计算完成后同样使用 \texttt{MPI\_Allgatherv} 同步。最后每个小模数的 residue 由 rank 0 取出并参与 CRT 合并。

v2 的优点是 MPI 并行深入到了 NTT 内部，理论上可以突破“四个小模数最多四个任务”的限制；缺点是通信频率高。一次 NTT 有 $\log_2 N$ 层，正变换、逆变换以及点值乘法都会触发同步，通信开销很容易超过计算分摊带来的收益。

\subsubsection{v3：在 stage 级 MPI 中加入 Barrett 规约}

v3 保留 v2 的 MPI 通信结构，即仍然按 butterfly block 分配任务，并在每层后使用 \texttt{MPI\_Allgatherv} 同步。它的优化点不在通信，而在每个 rank 本地执行 butterfly 时的高频模乘。

NTT 中最常见的模乘形式是：
\begin{lstlisting}[language=C++]
return x * y % mod;
\end{lstlisting}
其中 \texttt{\% mod} 对应整数除法/取模，延迟通常高于普通乘法、加法和移位。由于 butterfly 中旋转因子乘法出现次数为 $O(N\log N)$，点值乘法和逆变换缩放也需要大量模乘，所以减少取模开销可以降低计算部分的常数时间。

Barrett 规约的思想是：当模数 $mod$ 固定时，预先计算一个近似倒数，用乘法和右移估计商，从而避免每次都做除法。对固定小模数 $mod$，预计算：
\[
\mu=\left\lfloor\frac{2^{64}}{mod}\right\rfloor
\]
对于待规约的 $x$，有：
\[
\frac{x}{mod}\approx \frac{x\mu}{2^{64}}
\]
所以估计商为：
\[
\hat{q}=\left\lfloor\frac{x\mu}{2^{64}}\right\rfloor
\]
代码中通过 128 位乘法后取高 64 位实现：
\begin{lstlisting}[language=C++]
u64 q = (u64)(((u128)x * br.mu) >> 64);
\end{lstlisting}
再计算候选余数：
\[
\hat{r}=x-\hat{q}\cdot mod
\]
由于估计商可能有很小误差，需要用条件减法把结果修正回 $[0,mod)$。本实验四个小模数均约为 $10^9$ 量级，两个模数元素相乘仍在 \texttt{uint64\_t} 范围内，因此使用两次条件减法即可覆盖修正范围。

代码实现中为每个小模数构造一个 \texttt{BarrettReducer}：
\begin{lstlisting}[language=C++,title=Barrett 参数和规约函数]
struct BarrettReducer {
    u64 mod;
    u64 mu;
};

static inline BarrettReducer make_barrett(u64 mod) {
    BarrettReducer br;
    br.mod = mod;
    br.mu = (u64)((((u128)1) << 64) / mod);
    return br;
}

static inline u64 barrett_reduce(u64 x, const BarrettReducer &br) {
    u64 q = (u64)(((u128)x * br.mu) >> 64);
    u64 r = x - q * br.mod;
    if (r >= br.mod) r -= br.mod;
    if (r >= br.mod) r -= br.mod;
    return r;
}

static inline u64 mul_mod_barrett(u64 x, u64 y,
                                  const BarrettReducer &br) {
    return barrett_reduce(x * y, br);
}
\end{lstlisting}

在本实验中，Barrett 主要替换以下位置：
\begin{enumerate}
    \item 旋转因子数组 \texttt{roots[k]} 的递推模乘；
    \item butterfly 中 \texttt{f[base+k+half] * roots[k]} 的模乘；
    \item 点值乘法阶段 \texttt{A[i] * B[i]} 的模乘；
    \item 逆 NTT 最后乘 \texttt{inv\_n} 的缩放模乘。
\end{enumerate}

CRT 最后的大模数合并阶段没有使用 Barrett，而是继续使用 \texttt{\_\_uint128\_t} 处理。原因是 CRT 合并的数值范围和小模数 NTT 内部不同，且调用频率远低于 butterfly 模乘；优先优化小模数 NTT 内部的高频模乘收益更高。

因此，v3 可以看作“MPI stage 级通信结构 + 本地 Barrett 模乘优化”。

\subsubsection{v4：MPI stage + Barrett + DIF/DIT}

v4 是 v3 的进一步流程优化，MPI 通信方式仍然沿用 v2/v3：每层 butterfly block 按 rank 划分，每层结束后通过 \texttt{MPI\_Allgatherv} 同步完整数组；本地模乘仍使用 Barrett 规约。

与 v3 相比，v4 把 NTT 正变换和逆变换流程改为前面 v5 中介绍过的 DIF/DIT 组合，因此这里不再重复其数学过程。实现上，正变换调用 DIF 版本，逆变换调用 DIT 版本：
\begin{lstlisting}[language=C++,title=v4 的 stage + Barrett + DIF/DIT 主流程]
ntt_mpi_dif_forward_barrett(A, nm.mod, nm.root, comm);
ntt_mpi_dif_forward_barrett(B, nm.mod, nm.root, comm);
pointwise_mpi_stage_barrett(A, B, br, comm);
intt_mpi_dit_inverse_barrett(A, nm.mod, nm.root, comm);
\end{lstlisting}

DIF/DIT 主要减少显式位逆序置换造成的不连续访存和交换开销，Barrett 主要减少模乘中的取模开销，二者都属于计算端优化。它们可以改善每个 rank 本地执行 butterfly 的效率，但不会改变 stage 级 MPI 每层同步的通信模式。因此 v4 的意义在于观察：在通信结构不变的前提下，连续叠加本地计算优化能够把 stage 级方案推进到什么程度。

\section{结果分析}

\subsection{v1 与 v2 的对比}

v1 使用 CRT 模数级并行，通信主要发生在非 0 进程将 residue 数组发送回 rank 0 的阶段。由于四个小模数下的 NTT 计算完全独立，v1 的同步和通信次数较少，适合大模数 CRT 场景。但 v1 的并行粒度较粗，最多只有四个模数任务，当 MPI 进程数超过四时，多余进程不能得到有效利用。

v2 将 MPI 并行深入到每个小模数的 NTT 内部。该方法更符合 NTT stage 任务划分思想，同一层 butterfly block 由不同进程计算。但 NTT 每层结束后都必须同步完整数组，因此频繁调用 \texttt{MPI\_Allgatherv}，通信开销较高。从实测结果看，v1 在第 4 号样例上的平均时间为 $136.515$ ms，而 v2 为 $349.905$ ms，相对 v1 的加速比只有 $0.39$，即明显变慢。这说明对本实验规模和服务器环境而言，stage 级细粒度 MPI 并行带来的计算分摊收益小于层间全局通信开销。

\subsection{Barrett 规约的影响}

v3 使用 Barrett 规约替代小模数 NTT 中高频出现的普通取模乘法。理论上，Barrett 可以用乘法、位移和条件减法替代整数除法，从而降低 \texttt{x*y\%mod} 的代价。由于 NTT butterfly 中模乘出现次数为 $O(n\log n)$，该优化有较高的潜在收益。

实测中，v3 的第 4 号样例平均时间为 $319.365$ ms，相比 v2 的 $349.905$ ms 约提升 $8.7\%$。这说明 Barrett 规约确实降低了小模数 NTT 内部模乘的常数开销。不过 v3 仍然慢于 v1，原因在于 v3 没有改变 stage 策略的通信结构，每一层 NTT 之后仍然需要 \texttt{MPI\_Allgatherv} 同步完整数组。因此 Barrett 优化能够改善计算部分，但无法消除 stage 级 MPI 并行中的主要通信瓶颈。

\subsection{DIF/DIT 优化的影响}

v4 通过 DIF 正变换和 DIT 逆变换配合，避免显式 \texttt{bit\_reverse}。位逆序置换属于不连续访存，对 cache 不友好。去掉该步骤能够减少额外交换和访存开销。

实测中，v4 的平均时间为 $290.947$ ms，相比 v3 的 $319.365$ ms 继续提升约 $8.9\%$。这说明 DIF/DIT 对本地计算流程和访存模式有正向作用，尤其是避免显式位逆序置换后，减少了一部分额外访存和交换开销。但 v4 仍然沿用 stage 策略，每层依旧需要 \texttt{MPI\_Allgatherv} 同步，所以虽然 v4 是 stage 系列中最快的版本，平均时间仍然高于 v1 的 $136.515$ ms。

\subsection{v5 混合并行效果分析}

v5 在 v1 的 CRT 模数级 MPI 并行基础上进一步加入 DIF/DIT 流程，并继续保留进程内 OpenMP 和 SIMD 优化。它保留了 v1 的低通信结构，避免了 v2--v4 中每层 NTT 的全局同步；同时，每个 MPI 进程内部对自己负责的小模数 NTT 使用线程级和指令级并行优化。

从结果看，v5 在 \texttt{np=4, OMP\_NUM\_THREADS=2} 时表现最好，第 4 号样例平均时间为 $67.734$ ms，相对 v1 的加速比为 $2.02$。这说明对 CRT 模数并行而言，最有效的策略是保持外层模数任务的粗粒度 MPI 划分，并在每个模数内部适度使用线程级并行和 SIMD。该配置总共使用 8 个核心，正好对应单节点 \texttt{nodes=1:ppn=8}，避免了跨节点调度和额外通信。

进一步将 OpenMP 线程数增加到 4，即 \texttt{np=4, OMP\_NUM\_THREADS=4}，理论上使用 16 个核心，但实测平均时间反而增加到 $91.944$ ms。该结果说明线程数并非越多越好。对于每个小模数 NTT 来说，OpenMP 并行区域、线程同步、内存带宽竞争和跨节点资源调度都可能带来额外开销。当每个 MPI 进程使用 4 个线程时，这些开销抵消了更多核心带来的收益。因此，本实验中 v5 的较优配置是 \texttt{np=4, OMP\_NUM\_THREADS=2}。

\section{问题与反思}

\subsection{perf 无法在 qsub 作业中使用}

实验初期曾尝试使用 \texttt{perf stat} 和 \texttt{perf record} 分析程序。登录节点上可以找到 \texttt{/usr/bin/perf}，但 qsub 作业分配到的计算节点中没有该命令。由于实验要求通过 qsub 提交 MPI 程序，直接在登录节点运行 \texttt{mpiexec} 不符合正式实验流程。因此最终报告采用 qsub 输出的程序计时结果作为性能依据。

\subsection{MPI 任务粒度选择}

v1 和 v2 体现了两种典型的 MPI 任务划分思路。v1 是粗粒度任务并行，通信少但扩展性有限；v2 是细粒度 stage 并行，任务划分更深入但通信频繁。实测结果表明，在当前问题规模下，粗粒度 CRT 模数级 MPI 并行明显优于 stage 级 MPI 并行。NTT 算法本身存在严格的层间依赖，因此细粒度 MPI 并行需要在计算收益和同步开销之间权衡，不能简单认为任务划分越细越好。

\subsection{优化叠加不一定线性收益}

Barrett 和 DIF/DIT 都是计算端优化。若程序主要瓶颈在本地 butterfly 模乘和访存，它们可以带来明显收益；若程序主要瓶颈在 MPI 通信和同步，则计算端优化的收益会被通信开销掩盖。因此报告分析时不能只看优化是否“理论更快”，还需要结合具体实现和运行环境判断瓶颈。

v5 的结果也说明，混合并行的线程数选择需要谨慎。相较于 \texttt{OMP\_NUM\_THREADS=2}，继续增加到 \texttt{OMP\_NUM\_THREADS=4} 并没有带来加速，反而使平均时间从 $67.734$ ms 增加到 $91.944$ ms。这说明更多核心可能引入线程调度、同步和内存竞争开销，实际最优配置需要通过实验确定。

\section{总结}

本实验在前序 OpenMP、SIMD、CRT NTT 代码基础上实现了五个 MPI 版本。v1 使用 CRT 模数级 MPI 并行，结构简单、通信少，同时保留进程内部 OpenMP 和 SIMD 优化，适合作为大模数 CRT 场景的基础 MPI 实现。v2 实现 NTT stage 级 MPI 并行，将每层 butterfly block 分配给不同进程，并通过 \texttt{MPI\_Allgatherv} 完成层间同步。v3 在 v2 基础上加入 Barrett 规约，减少小模数 NTT 中高频模乘的取模开销。v4 进一步使用 DIF/DIT 流程优化，避免显式位逆序置换。v5 回到 v1 的低通信 CRT 模数级 MPI 框架，在已有 OpenMP/SIMD 基础上进一步采用 DIF/DIT 流程，是本次实验中性能最好的版本。

实测结果显示，v1 在第 4 号大规模样例上的平均时间为 $136.515$ ms；v2 由于频繁层间同步，平均时间增加到 $349.905$ ms；v3 和 v4 分别通过 Barrett 和 DIF/DIT 将 stage 系列优化到 $319.365$ ms 和 $290.947$ ms，但仍然受限于通信开销。v5 在 \texttt{np=4, OMP\_NUM\_THREADS=2} 下平均时间降至 $67.734$ ms，相对 v1 加速约 $2.02$ 倍，是最优配置。

通过这些版本，可以系统比较粗粒度任务并行、细粒度 stage 并行、模乘规约优化、NTT 流程优化以及 MPI+OpenMP 混合并行对性能的影响。实验说明，在 MPI 程序中，通信和同步开销往往会显著影响最终性能；因此并行算法设计不能只关注计算部分的并行度，还需要综合考虑通信频率、任务粒度、线程数量和数据同步方式。
