\section{实验一：矩阵与向量内积}

\subsection{问题描述}
n矩阵的每一列与给定向量的内积，比较不同算法对时间造成的影响。
计算给定n*

\subsection{代码实现}

\subsubsection{朴素算法}
我们用N*N的二维数组s表示该矩阵，用长为N的一维数组v表示给定向量，在朴素算法中，s[i][j]表示矩阵中第i行第j列数，则在计算过程中，我们需要不停切换二维数组所在行，代码如下

\begin{lstlisting}[title=逐列访问平凡算法,frame=trbl,language={C++}]
void f_normal(int n){
	for(int i=1;i<=n;i++){
		sum[i] = 0;
	}
	for(int i=1;i<=n;i++){
		for(int j=1;j<=n;j++){
			sum[i] += s1[j][i]*v[j];	
		}
	}
}

\end{lstlisting}

\subsubsection{cache优化算法}
计算机存储系统采用分级架构，从高速到低速依次为寄存器、L1Cache、L2Cache、L3Cache、主存、外存。CPU 访问数据时，会优先从 Cache 中读取，Cache 的基本访问单位是缓存行（Cache Line），其核心特性是：一次内存访问可读取一整块连续的内存数据，从而大幅提升访问效率。

所以我们可以想到，在计算时cache取Cache Line时会将相邻数据同时取到，由于二维数组的存储原理，相邻数据中储存的就是该行后面的，所以我们可以利用这个原理，将第i行每一列与给定向量相乘的结果储存起来，逐行计算，遍历完二维数组后sum[i]中存储的就是第i列与给定向量相乘的记过，通过这种方式就提高了cache的命中率，从而提高了程序的整体效率,

\begin{lstlisting}[title=Cache优化算法,frame=trbl,language={C++}]
void f_cache(int n){
	for(int i=1;i<=n;i++){
		sum[i] = 0;
	}
	for(int i=1;i<=n;i++){
		for(int j=1;j<=n;j++){
			sum[j] += s[i][j]*v[i];
		}
	}
}
\end{lstlisting}

\subsubsection{循环展开算法}
由于使用循环计算会进行许多额外的比较操作与加法运算，所以我们可以考虑将循环部分展开，即通过降低循环的次数来提高代码运行效率，可以预见的，当完全展开循环时代码运行效率最高，但是此时代码量会上升许多，所以我们要在两者间取得平衡。这里我们将每四次加法进行展开，代码如下


\begin{lstlisting}[title=循环展开算法,frame=trbl,language={C++}]
void f_unroll(int n){
	for(int i=1;i<=n;i++){
		sum[i] = 0;
	}
	for(int i=1;i<=n;i++){
		int j;
		for(int j = 1;j<=n-4;j+=4){
			sum[j] += s[i][j]*v[i];
			sum[j+1] += s[i][j+1]*v[i];
			sum[j+2] += s[i][j+2]*v[i];
			sum[j+3] += s[i][j+3]*v[i];
		}
		for(;j<=n;j++){
			sum[j] += s[i][j]*v[i];
		}
	}
}
\end{lstlisting}

\section{实验二：数组求和与指令级并行优化}

\subsection{问题描述}

计算给定 $n$ 个整数的和，比较平凡链式累加、两路并行累加（超标量优化）以及递归分治求和三种算法的运行效率，分析指令依赖与指令级并行（ILP）对程序性能的影响。


\subsection{代码实现}

\subsubsection{朴素算法（逐个累加）}
采用单累加器逐个遍历数组元素，所有加法操作形成一条数据依赖链，CPU 必须等待前一次加法完成才能继续执行，无法利用超标量处理器的多发射与并行能力，代码如下。

\begin{lstlisting}[title=逐一遍历平凡求和算法,frame=trbl,language={C++}]
long long sum_normal(int n) {
    long long sum = 0;
    for (int i = 0; i < n; i++) {
        sum += arr[i];
    }
    return sum;
}
\end{lstlisting}

\subsubsection{两路并行超标量优化算法}
现代 CPU 支持指令级并行（ILP），可以同时执行多条无数据依赖的指令。本算法将求和分为两条独立累加链，打破串行依赖，使 CPU 能够并行执行加法操作，从而提高运算效率。

\begin{lstlisting}[title=两路并行超标量优化算法,frame=trbl,language={C++}]
long long sum_ilp(int n) {
    long long sum1 = 0, sum2 = 0;
    int i;
    for (i = 0; i + 1 < n; i += 2) {
        sum1 += arr[i];
        sum2 += arr[i + 1];
    }
    for (; i < n; i++) {
        sum1 += arr[i];
    }
    return sum1 + sum2;
}
\end{lstlisting}

\subsubsection{递归对称归约优化算法}
该算法采用递归归约思想，不断将数组首尾对称位置的元素相加，将结果存入数组前半段，并递归将问题规模折半，最终在数组首位得到总和。该方法有效降低数据依赖，提升并行性。

\begin{lstlisting}[title=递归对称归约求和算法,frame=trbl,language={C++}]
void sum__recursive1(int n) {
    if (n == 1) return;
    for (int i = 0; i < n / 2; i++) {
        c[i] += c[n - i - 1];
    }
    sum__recursive1(n / 2);
}
\end{lstlisting}

\subsubsection{迭代倍增优化算法}
该算法采用自底向上的迭代倍增思想，将相邻元素两两相加并不断折半归约，无递归开销、无长依赖链，内存访问连续，能够充分利用 CPU 流水线与缓存特性。

\begin{lstlisting}[title=迭代倍增求和算法,frame=trbl,language={C++}]
long long sum__recursive2(int n) {
    for (long long m = n; m > 1; m /= 2) {
        for (long long i = 0; i < m / 2; i++) {
            c[i] = c[i * 2] + c[i * 2 + 1];
        }
    }
    return c[0];
}
\end{lstlisting}

从实验结果可以得到以下核心结论：

    \item \textbf{归约算法的性能特性}：对称归约与迭代倍增两种归约算法，通过构建低依赖的并行计算结构，耗时均低于平凡算法，在大规模数据下性能优势更明显。其中迭代倍增算法无递归函数调用开销，在大规模数据下性能略优于递归对称归约算法。
    \item \textbf{规模对性能差异的影响}：随着数据规模的增大，内存访问延迟的占比逐渐提升，指令级并行的优化收益相对缩小，但两路并行算法始终保持最优性能，验证了指令级并行优化的普适性。
\end{enumerate}

实验结果充分验证了：通过打破数据依赖、构建独立计算链来挖掘指令级并行，是提升CPU计算密集型程序性能的有效手段。

\section{总结与反思}

\subsection{实验总结}
本次实验通过两组对比测试，验证了程序性能优化的两条关键路径。
实验一表明，优化数据访问的空间局部性可以显著提高缓存命中率，大幅降低内存访问延迟，从而使程序性能成倍提升；
实验二表明，打破数据依赖、利用指令级并行与分治归约，能够充分发挥CPU超标量执行能力，有效减少流水线阻塞，进一步提升计算效率。
两组实验均说明，良好的局部性与并行结构是程序高效运行的核心。

\subsection{实验反思}
在实验过程中，部分优化算法在小规模数据下优势不明显，只有在数据量较大时才能体现出明显效果，说明性能优化具有明显的数据规模依赖性。
同时，递归类算法虽然并行性更好，但会带来额外的函数调用开销，需要在代码结构与运行效率之间做出权衡。
此外，实验也让我认识到，手写优化需要结合硬件特性与编译器行为，盲目改写代码不一定能带来性能收益。

\subsection{心得体会}
通过本次实验，我更加深刻地理解了计算机存储层次与指令流水线对程序性能的影响，学会了使用VTune分析性能瓶颈，并掌握了缓存优化、循环展开、指令级并行等基本优化方法。
在今后的程序设计中，我会更加注重数据访问模式与计算依赖结构，在编写代码时兼顾正确性与高效性。
